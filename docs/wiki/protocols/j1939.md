# J1939 over classic CAN

## Frame structure

J1939 uses 29-bit extended CAN identifiers. Standard PGN extraction must handle PDU1 (PF < 240, PS is destination and is excluded from PGN) and PDU2 (PF >= 240, PS is group extension). Classic CAN data fields are 0–8 bytes. J1939-21 transport protocol segments larger messages using TP.CM and TP.DT; keep raw segments and reassembled payload linked in the capture.

## Current DieselCairn fixtures

The app currently has mappings for EEC1 (PGN 61444 / `0xF004`), EEC2 (`0xF003`), ET1 (`0xFEEE`), fuel economy (`0xFEF2`), intake manifold (`0xFEF6`) and ambient conditions (`0xFEF5`), plus a generic synthetic ETC2 test fixture. Their presence in code does not prove the PB305 broadcasts them or that Allison uses the fixture layout.

## Simulator controls required

Bitrate; node source address/address claims; PGN/priority/payload; standard vs extended identifier validation; TP segmentation/reassembly; DM1/DM2 fixtures; request timeout; bus load/arbitration; bus-off/error counters; deliberate malformed DLC/identifier; timestamps; replay; and independent controller/transceiver/power state. Do not advertise CAN-FD as supported.

## Evidence

Use the repository `ProtocolSpec.md` as the codebase profile, and the [ISOBUS PGN/SPN data reference](https://www.isobus.net/isobus/pGNAndSPN/17187?type=PGN) as an external dictionary reference. A dictionary is not a capture from this bus.
