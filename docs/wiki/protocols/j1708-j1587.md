# J1708 physical/data link and J1587 messages

## Layer responsibilities

| Layer | Function | DieselCairn implementation boundary |
|---|---|---|
| J1708 | Two-wire shared-bus electrical signaling and access arbitration | Dedicated compliant PHY, adapter-side timed UART/driver control, echo/collision detection and retry |
| J1587 | MID, PID, data and checksum message format over J1708 | Parse and validate raw messages; decoded PID semantics need a documented dictionary |

Reference profile: 9,600 baud, 8 data bits, no parity, 1 stop bit; maximum 21 bytes for the ordinary J1587 message profile including MID and checksum. Checksum makes the unsigned byte sum modulo 256 equal `0xFF`. The adapter must observe ten consecutive high bit-times before priority timing. Priority delay is `P_D = P × 2 × tB`, where `tB` is a bit time; access arbitration, collision and retry need device-side timing. Validate all behavior against the applicable SAE revision and selected transceiver reference design.

## Physical design constraints

J1708 is not a generic RS-485 application. Use a J1708 reference circuit and verify driver polarity, loading/bias/filter network, isolation, common-mode/fault rating, ESD/transients, supply and connector. Do not add a CAN 120-ohm termination by habit. No vehicle connector pinout is confirmed for this PB305; do not use a guessed 6-pin/9-pin mapping.

## Simulator controls

MID and raw PID/data editor; checksum auto-calc and corruption; 21-byte size limit; message gap; priority 1–8; observed idle count; collision/echo mismatch; retry/backoff; receive framing fault; stuck-dominant/noise fixture; node online/offline; independent J1708 transceiver/power/firmware states; capture and replay. All synthetic events carry `SIMULATOR` provenance.
